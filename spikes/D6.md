## Chosen model (v1)

### Direct-download installs (GitHub Releases MSI / NSIS / AppImage / DMG)

1. Ship **Tauri updater** (`tauri-plugin-updater` **2.14.1** + `@tauri-apps/plugin-updater` **2.14.1**) in `app` at scaffold (HZ-029).
2. Configure:
   - `bundle.createUpdaterArtifacts: true`
   - `plugins.updater.pubkey` = public half of owner-held minisign keypair
   - `plugins.updater.requireSignedVersion: true` (reject version confusion on unsigned endpoint JSON)
   - `endpoints`: HTTPS static `latest.json` on GitHub Releases (or CDN mirroring the same file)
   - Never set `dangerousInsecureTransportProtocol`
3. UI: check is **opt-in / prompted**; never silent install without user consent. Windows `installMode` prefer `basicUi` or prompted flow over quiet.
4. On verify failure or network failure: keep running the installed version; show an honest error; offer manual download link.
5. Updater minisign key is **separate** from Authenticode / Apple Developer ID (D5). Both layers apply to public Windows/macOS artifacts.

### Channel installs

| Channel | Update path | In-app Tauri updater |
|---|---|---|
| winget `Hertzline.Hertzline` | `winget upgrade --id Hertzline.Hertzline` | Off / not primary (avoid dual writers) |
| Flatpak (Flathub) | `flatpak update` / GNOME Software / Discover | Off (sandbox + Flathub remote owns updates) |
| Homebrew cask | `brew upgrade --cask` (after owner-approved cask) | Off |
| deb / rpm / AUR | Distro / user package manager | Off for packaged builds |

Channel builds document "Updates come from your package manager" in the About / Updates UI. Direct-download builds document "Signed in-app updates" plus manual fallback.

### Manual fallback (all installs)

Website `/download/` (HZ-046 / HZ-052) always lists version, per-OS URLs, and SHA-256 checksums. Manual reinstall remains valid if in-app or channel update fails.

## Signature verification path (required)

```
build (with TAURI_SIGNING_PRIVATE_KEY)
  -> installer + .sig (minisign)
  -> latest.json embeds signature text (not a path/URL)
  -> app check() over HTTPS
  -> download bytes
  -> verify(pubkey, signature, requireSignedVersion)
  -> install only if verify passes
  -> else abort; keep current binary
```

Failure modes (documented for app + packaging):

| Failure | Behavior |
|---|---|
| Bad / missing signature | Refuse install; keep current version |
| Announced version != signed version | Refuse (`requireSignedVersion`) |
| HTTP / non-TLS endpoint in production | Rejected by Tauri defaults |
| Missing private key at release | Fail release job closed (align with D5 never-skip-signing) |
| Lost private key | Cannot push signed updates to existing installs; recovery = new key + reinstall messaging (owner ops) |

## Owner gates (recorded)

Per `RULES.md` / D5:

1. Generate and custody `TAURI_SIGNING_PRIVATE_KEY` (and optional password). Agent never commits private keys.
2. Publish `pubkey` only in `app` config / docs.
3. No unsigned public updater artifacts.
4. Store / Flathub / Homebrew / winget submissions remain owner-approved separately.

## Decision

**Chosen:**

1. **Direct downloads:** Tauri in-app updater with **mandatory** minisign verification and **`requireSignedVersion: true`**; pin **tauri-plugin-updater / @tauri-apps/plugin-updater 2.14.1** (MIT OR Apache-2.0) at app scaffold; re-verify versions then.
2. **Channel installs:** platform updaters only (winget / Flatpak / Homebrew / distro); in-app updater off for those builds.
3. **Manual download + SHA-256** always available; never the only path for direct installs once keys exist.
4. **Never** ship signature-optional or silent unsigned updates; fail closed.
5. Key generation and first live endpoint are **owner-gated**; until keys exist, UI may offer "Open download page" only (honest manual interim), never fake a working auto-update.
